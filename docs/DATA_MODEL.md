# Data model — `public/plotto.json`

Generated by `scripts/build-data.mjs`. Top-level shape:

```jsonc
{
  "meta": { … },
  "characterSymbols": [ … ],
  "masterplot": { "aClauses", "bClauses", "cClauses", "bClauseIndex" },
  "conflicts": [ … ],
  "danglingLinks": [ … ]
}
```

## `meta`

Source attribution, `generatedAt`, and a `counts` object (conflicts, permutations,
groups, subgroups, A/B/C clause counts, characterSymbols, danglingLinks). The app reads
`counts` for the header.

## `characterSymbols[]`

Cook's symbol key.

```jsonc
{ "symbol": "A-2", "description": "male friend of A", "gender": "m", "relationOf": "A" }
```

`gender` (`"m"|"f"|null`) and `relationOf` (`"A"|"B"|null`) are derived from the
description. Powers the legend and the name editor.

## `masterplot`

- `aClauses[]` (15), `bClauses[]` (62), `cClauses[]` (15) — each `{ number, text }`.
  These are the protagonist / action / ending options of the masterplot frame.
- `bClauseIndex` — `{ "<bClauseNumber>": { conflicts: string[], note: string|null } }`.
  Cook's index of which conflicts open each B-clause; drives the opening-conflict step.
  (B-clause 62 is _"All Conflicts"_ and carries a `note` instead of ids.)
- `cClauseIndex` — `{ "<cClauseNumber>": string[] }`. Parsed from the back-matter
  *Classification by Symbols*, where terminal conflicts are prefixed with their C-clause
  number, e.g. `(1) A … commits suicide 281b`. Maps each ending (C-clause 1–14; 15 is the
  "any fate" wildcard, unlisted) to the conflicts that terminate the story that way — 1,213
  validated pairs, 873 distinct terminal conflicts. Drives the ending guidance (badges,
  destination banner). `data.ts` inverts this into `terminalFor: Map<conflictId, number[]>`.

## `conflicts[]`

```jsonc
{
  "id": "347",
  "group": "Love and Courtship",     // one of 3 groups
  "subgroup": "Marriage",            // or null
  "bClause": 50,                     // the B-clause this conflict sits under
  "characters": ["A", "A-3", "B", "F-B"],  // surface symbols found in the text
  "permutations": [ Permutation, … ],
  "leadUps":  ["23", "331", "332"],  // deduped union of base target ids (graph-level)
  "carryOns": ["348", "377", "379"]  // ""
}
```

`leadUps` / `carryOns` at the conflict level are the **deduped union** across
permutations — convenient for a future graph view. The **builder uses the
permutation-level refs** instead, for precision.

### `Permutation`

```jsonc
{
  "letter": "a",             // or null when the conflict has a single unlettered block
  "text": "A, seeking to uphold a lofty conception of duty, secretly abandons B … **",
  "leadUps":  [ Ref, … ],    // from the PRE: line
  "carryOns": [ Ref, … ]     // from the POST: line
}
```

`text` is **verbatim** Cook, character symbols intact. `*` / `**` / `***` mark the
phrase phases a reference's phase marker can point into.

### `Ref` — one cross-reference

```jsonc
{
  "raw": "1106 -* ch B to A",   // always the verbatim source
  "kind": "ref",                // "ref" | "sequence" | "alt"
  "targetConflict": "1106",     // resolvable base id (null for bare "(a)" pointers)
  "targetPermutations": ["a"],  // [] = the whole conflict
  "phase": "-*",                // phrase-range marker, or null
  "transform": "ch B to A",     // adaptation note, verbatim, or null
  "sequence": [ Ref, … ],       // present when kind === "sequence" (compound "123; 456")
  "alt":      [ Ref, … ]        // present when kind === "alt" ("123 or 456")
}
```

`options.ts` flattens these into `StepOption`s for the UI: a `sequence` yields its first
element as the immediate option plus a "then → …" chain hint; an `alt` yields each branch.

## `danglingLinks[]`

References whose target id doesn't resolve — surfaced, not silently rewritten.

```jsonc
{ "from": "214", "permutation": null, "direction": "carryOn", "target": "3633", "raw": "3633" }
```

Currently one entry: the `3633` typo in conflict 214 (a source typo for `363`).

## Reference syntax cheat-sheet (from Cook)

| Notation | Meaning |
| --- | --- |
| `112` | link to conflict 112 |
| `347a, b, c` | variants a/b/c of conflict 347 |
| `123; 456` | **compound** — 123 then 456 |
| `123 or 456` | **alternation** |
| `-*`, `**-***` | use a **phrase range** of the target's `*`-delimited text |
| `ch X to Y` | change character X to Y |
| `tr X & Y` | transpose (swap) X and Y |
| `add X` / `eliminate "…"` | add / remove a character |
